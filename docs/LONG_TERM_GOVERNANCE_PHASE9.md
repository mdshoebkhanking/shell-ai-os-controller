# Phase 9 Long-Term Governance

Shell starts as a creator-led project, but it should be able to grow beyond one
developer over time.

## Governance Stages

1. Creator-led.
2. Trusted contributor review.
3. Maintainer roles.
4. Security review group.
5. Plugin marketplace review group.
6. Formal steering group if the project becomes large.

## Maintainer Workflows

- triage weekly
- label issues
- review PRs with tests
- publish release notes
- update roadmap
- close unsafe requests clearly

## Decision Records

Use lightweight docs for decisions that affect:

- public APIs
- plugin permissions
- security policy
- distribution
- governance
- monetization

## Release Leadership

Every release should have:

- release owner
- verification checklist
- package checksum
- known issues
- rollback notes
- post-release monitoring

## Ecosystem Governance

Plugin and automation marketplace governance needs:

- permission policy
- signing requirements
- review checklist
- abuse reporting
- quarantine policy
- vulnerability disclosure path

## Final Goal

Grow a maintainable AI automation ecosystem where trust, safety, and useful
workflows matter more than hype.
