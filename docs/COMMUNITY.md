# Community Guide

## Project Tone

Shell should be practical, transparent, and beginner-friendly.

## Community Promise

This project welcomes people who care about useful AI automation, but it will
not reward unsafe shortcuts. Good contributions make Shell easier to install,
easier to understand, safer to operate, or easier to debug.

## Discussions

Use discussions for:

- Setup help.
- Feature ideas.
- Show-and-tell demos.
- Roadmap feedback.

Use issues for:

- Reproducible bugs.
- Specific feature requests.
- Documentation gaps.

Use private reporting for:

- Secrets.
- Remote-control bypasses.
- Arbitrary code execution.
- Vulnerabilities.

## Good First Issues

Good beginner tasks:

- Improve docs.
- Add screenshots.
- Improve error messages.
- Add tests for existing behavior.
- Fix small UI layout bugs.
- Verify install flows on real machines.
- Add examples for one safe workflow at a time.

## Maintainer Standards

- Be direct and respectful.
- Ask for repro steps.
- Close unsafe requests clearly.
- Keep roadmap realistic.
- Label capability as verified, conditional, experimental, or planned.
- Link users to the troubleshooting or trust docs when behavior is limited.
