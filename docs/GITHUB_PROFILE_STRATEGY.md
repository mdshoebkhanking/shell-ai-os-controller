# GitHub Profile Strategy

This file is a practical plan for making the public GitHub presence look
professional before pushing the project.

## Profile Repository Setup

GitHub shows a profile README when:

- You create a public repository with the same name as your GitHub username.
- That repository has a root `README.md`.

For username `mdshoebking`, create:

```text
repo name: mdshoebking
file: README.md
```

Copy the prepared profile README from:

```text
github-profile/README.md
```

## Pinned Repository Plan

Pin up to six strong repositories:

1. `shell-ai-os-controller` - main flagship AI desktop automation project.
2. A small polished AI tool repo - for example, image generator, voice tool, or
   Telegram automation utility.
3. A clean Python automation utility.
4. A documentation/demo repo showing architecture diagrams and install guides.
5. A frontend/UI experiment if you want to show design ability.
6. A learning/build log repo only if it is organized and professional.

Avoid pinning:

- Broken experiments.
- Empty repos.
- Repos with no README.
- Repos containing secrets, raw logs, or unlicensed code.

## Profile Design Rules

- Lead with what you build, not hype.
- Keep language professional and direct.
- Show one flagship project clearly.
- Use badges, but not too many.
- Keep contact links simple.
- Add screenshots only if they are clean and public-safe.

## Public Launch Checklist

- Profile README created.
- Shell repo README has real screenshots.
- License and security files are present.
- No `.env`, logs, tokens, or private screenshots are committed.
- Release zip passes production readiness.
- First release has a clear changelog.
- Demo video link is added when available.
