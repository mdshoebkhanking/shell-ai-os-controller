What Shell AI OS Controller is
------------------------------
Shell AI OS Controller is a local-first Windows desktop assistant/OS-control layer. It is not a real operating system replacement. It is a Python backend plus Electron/React Web UI that routes natural language and voice requests into local tools, OS automation, file/document creation, AI providers, offline LLM/TTS/STT, and guarded workflows.

Core product idea:
- Normal desktop automation and basic make/build tasks should work offline.
- Hard/creative/big tasks can use cloud LLMs only when the user has configured API keys and enabled online mode.
- Actions should go through Shell's local action/tool layer. Cloud models can plan or generate content, but local Shell owns file writes and execution.

Primary platform:
- Windows 10/11 is the primary release target.
- macOS/Linux can run some development paths, but many OS-control tools are Windows-only.

Main architecture
-----------------
High-level flow:
1. User uses Electron/React UI or voice.
2. Electron main process talks to Python backend through `shell_electron_bridge.py`.
3. Python backend host is `shell_web_ui/host.py`.
4. Natural language routing happens in `shell_nl_router.py`.
5. Tools execute through `shell_tool_gateway.py` and catalog metadata from `shell_tool_catalog.py`.
6. Safety and policy checks live across `shell_safety_gate.py`, `shell_safe_executor.py`, `shell_production_guard.py`, and approval handling in `shell_web_ui/host.py`.
7. Build/release tooling is in `tools/`, `.github/workflows/`, and Windows batch/command launchers.

Offline and online task model
-----------------------------
Shell now has a two-level make/build capability model:

1. Level 1 / offline / local basic
   - No cloud API required.
   - Handles simple PDFs, notes, summaries, checklists, Markdown/text, simple static websites, landing pages, simple HTML/CSS/JS, small Python/PowerShell helpers, and normal desktop automation.
   - Implemented in `shell_task_mode.py`, `shell_make_modes.py`, `shell_code_engine.py`, `shell_web_ui/host.py`, and `shell_nl_router.py`.

2. Level 2 / online / cloud pro
   - Used for complex apps, production websites, large codebases, multi-page marketing sites, big documents, backend/auth/database work, and explicit "pro" requests.
   - Requires a configured cloud API key plus online/provider mode.
   - Cloud LLM should produce strategy/copy/code plans, but Shell still renders/writes/executes locally.
   - Supported key names are checked without exposing values: GOOGLE_API_KEY/GEMINI_API_KEY, OPENAI_API_KEY, ANTHROPIC_API_KEY, OPENROUTER_API_KEY, GROQ_API_KEY, MISTRAL_API_KEY, TOGETHER_API_KEY, HF_API_KEY/HUGGINGFACE_API_KEY.

Movie script behavior
---------------------
The chat backend was changed so "write a full movie script from start to end" no longer collapses to only a logline and a vague ending. Current behavior:
- It produces Acts/scenes and writes as much as practical.

- Movie script PDF routing keeps topic and destination and generates script-like content before file creation.
- Covered by tests in `tests/test_shell_web_ui_bridge.py` and `tests/test_nl_router.py`.
